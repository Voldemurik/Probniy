# Алгоритм обнаружения подписок — спецификация v1

Реализация: `backend/app/services/detector.py`. Параметры: `DetectorConfig` в `backend/app/config.py` — менять там, а не в коде.
Тесты: `backend/tests/test_detector.py` — каждый пункт ниже покрыт хотя бы одним тестом; новое правило = новый тест.

Статус: **v1 (пятница) реализована и проверена на трёх демо-профилях**. Разделы, помеченные «v2», — задачи субботы для BE и AI-2.

---

## 0. Определения (согласованы с `docs/definitions.md`, PM)

Подписка — это группа списаний одного сервиса, у которой:

1. интервалы между списаниями укладываются в один из периодов (см. §4) с допуском по дате;
2. суммы стабильны (±15 % от медианы) либо меняются **один раз ступенчато** (рост или снижение цены);
3. списаний не меньше минимума для периода (§4).

Не подписка (даже если регулярно): переводы физлицам и по СБП, снятие наличных, платежи по кредитам и рассрочкам, налоги и штрафы, ЖКУ и коммунальные платежи, зачисления. Также не рассматриваются покупки в категориях банка «супермаркеты», «кафе», «транспорт», «АЗС», «аптеки», «маркетплейсы» и подобных — там регулярность случайна.

Опорная дата — последняя дата в выписке (`meta.period_to`), а не «сегодня».

## 1. Отбор строк

* Берём только списания (`amount < 0`).
* Исключаем по ключевым словам в описании (`exclude_keywords`): «перевод», «p2p», «сбп», «снятие», «наличн», «atm», «кредит», «ипотек», «рассрочк», «долями», «налог», «штраф», «зарплат», «возврат», «жкх», «коммунал» и др.
* Исключаем по категории банка: `exclude_categories` (переводы, наличные, кредиты, ЖКХ…) и `purchase_categories` (супермаркеты, кафе, транспорт, АЗС, аптеки, маркетплейсы…).
* Если категорий у банка нет — работают только ключевые слова; ложных кандидатов больше, их отсечёт §7 и уверенность §9.

## 2. Нормализация описания → `merchant_key`

1. нижний регистр, `ё → е`;
2. убрать цифры и знаки препинания (`YANDEX.PLUS` → `yandex plus`, `APPLE.COM/BILL` → `apple com bill`);
3. убрать шумовые токены (`noise_tokens`): города, страны, `ooo/ип/llc`, `com/ru/www`, «оплата», «покупка» и т.п., а также токены из одной буквы;
4. если в результате содержится алиас из словаря `known_aliases` — ключ группы `known:<каноническое имя>`. Так `YANDEX.PLUS MOSCOW RUS`, `Yandex Plus` и `ЯНДЕКС ПЛЮС` попадают в одну группу без эмбеддингов;
5. иначе ключ — первые три оставшихся токена.

Словарь алиасов в v1 — минимальный (≈40 записей) и живёт в `config.py`. Полный словарь ведёт AI-1 в `data/merchants.yaml`; при появлении файла загрузчик словаря переезжает туда (задача BE, суббота).

## 3. Кластеризация (v2, AI-2)

`scan(..., cluster_fn=...)` принимает функцию `descriptions → cluster_id[]`. Если она передана, группы строятся по кластерам, а ключ группы — самый частый `merchant_key` внутри кластера (чтобы сохранить связь со словарём и категориями). Без неё группировка — по §2. Цель кластеризации — варианты, которых нет в словаре: `NETFLX`, `NFLX*`, опечатки, транслит.

## 4. Периодичность

Интервалы между соседними списаниями (дни), допуск `date_tolerance_days = 3` на каждую границу:

| Период | Интервал, дни | Минимум списаний | Особое условие |
|---|---|---|---|
| weekly | 6–8 | 4 | — |
| monthly | 27–33 | 3 | — |
| quarterly | 85–97 | 2 | — |
| yearly | 355–375 | 2 | только если охват выписки ≥ 13 месяцев |

Ряд принимается для периода, если **каждый** интервал либо попадает в диапазон, либо равен удвоенному диапазону (один пропуск, флаг `gap`); пропусков не больше `max_gaps = 1`. Из подходящих периодов выбирается тот, у которого больше доля «чистых» интервалов.

Регулярность (0–1) = 1 − среднее относительное отклонение интервалов от номинала (7/30/91/365 дней), минус 0,1 за каждый пропуск.

## 5. Суммы

Работаем с модулями сумм в порядке дат.

* **Пробный период.** Если списаний ≥ 3 и первое ≤ 1 ₽ или ≤ 10 % от медианы остальных — флаг `trial_converted`, первое списание исключается из проверки сумм и из `amount_history`.
* **Стабильно.** Все суммы в пределах ±15 % от медианы → `amount_current = медиана`, `amount_history = [первая дата → медиана]`.
* **Ступенчато.** Иначе ищем одну точку `k`, где до неё суммы стабильны вокруг своей медианы, после неё — вокруг своей, и **с каждой стороны не меньше двух списаний**. Если медианы различаются больше чем на 15 % — флаг `price_increase` / `price_decrease`, история из двух точек, `amount_current` — медиана после скачка. Требование «по два с каждой стороны» — защита от случайных троек похожих покупок (проверено на демо: без него АЗС становилась «подпиской с ростом цены»).
* **Иначе** группа отклоняется (ЖКУ с плавающей суммой не проходит).

Стабильность (0–1) = 1 − максимальное относительное отклонение от медианы своего участка.

## 6. Статус и следующее списание

* `inactive`, если от последнего списания до опорной даты прошло больше `1,5 × период`; тогда `next_charge_expected = null`, флаг `inactive` и находка «похоже, подписка уже отменена».
* Иначе `active`, `next_charge_expected = последнее + номинал периода`.
* Годовая подписка со следующим списанием в пределах 14 дней от опорной даты — флаг `renewal_soon`.

## 7. Дубли

Среди активных подписок категорий `video`, `music`, `cloud` две и больше → флаг `duplicate` на каждой и одна находка на категорию: «3 активные подписки категории «Видео»: … — возможно, достаточно одной».

## 8. Название и категория

Из словаря (`known_categories`), если ключ известен; иначе имя — ключ группы с заглавных букв, категория `other`. В v2 AI-2 через `enrich_cluster` уточняет имя, категорию и заполняет `decoded` для агрегаторов (`APPLE.COM/BILL`, `GOOGLE *`, `YM*`, `CLOUDPAYMENTS *`).

## 9. Уверенность

```
confidence = 0.35·регулярность + 0.25·стабильность + 0.25·min(n/6, 1) + 0.15·известность
```

`n` — число списаний, `известность` = 1, если сервис в словаре (в v2 — или `is_subscription_likelihood ≥ 0.7` от AI-2). Значение округляется до сотых. Пороги для интерфейса: ≥ 0,8 зелёный, 0,5–0,8 жёлтый, < 0,5 серый.

Примеры с демо: 6 ровных списаний известного сервиса — 0,98–0,99; 3 списания известного — ≈ 0,87; 3 списания неизвестного мерчанта — ≈ 0,66 (жёлтый: «проверьте»).

## 10. Сборка результата

* `yearly_cost = amount_current × {52, 12, 4, 1}`, `monthly_cost = yearly / 12`.
* Сортировка: активные по `yearly_cost` по убыванию, затем неактивные; после сортировки — `id = s_001…`.
* `totals` — только активные.
* Находки: рост цены, пробный период, дубли, скорое продление, неактивна; в v2 добавится `decoded`.

## План v2 (суббота, BE + AI-2 + AI-1)

1. Подключить `cluster_fn` от AI-2 и словарь `data/merchants.yaml` от AI-1.
2. `enrich_cluster` для неизвестных ключей и агрегаторов → имя, категория, `decoded`, `известность`.
3. Настроить допуски по стенду AI-1 (сессия 15:00): `amount_tolerance`, `date_tolerance_days`, `min_charges`.
4. Разобрать спорные случаи из `definitions.md`: образовательные рассрочки (Skillbox), «Литрес» с двумя списаниями, пополнение телефона на разные суммы.
