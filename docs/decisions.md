## D1 · 03.09 · Кейс и стек

**Решение.** Кейс 4 «Подписки-сканер» (Сбер). Веб-сервис: бэкенд Python 3.11 + FastAPI + pandas, фронтенд React + Vite + TypeScript (нестрогий) + Tailwind + Recharts. Telegram-бот — только в категории Could.

**Почему.** Главное действие — загрузка файла и чтение таблиц; демо идёт с проектора; дизайнер и фронтенд загружены полноценно только в вебе. Новичкам проще один язык на бэкенде и один — на фронтенде.

**Следствие.** Прототип дизайнера из Figma Make (React 19, Tailwind v4, pnpm) используем как источник визуальных решений, а не как кодовую базу фронтенда: FE собирает приложение по макетам заново на выбранном стеке. Компоненты из прототипа можно переносить кусками.

## D2 · 04.09 · Один адаптер LLM, два провайдера

**Решение.** Единственный внешний провайдер проекта — **OpenRouter** (один ключ, один счёт). Локальные модели — через **Ollama**. Оба ходят через один адаптер `backend/app/services/ai.py` с одним методом `chat_json(system, user, schema)`; переключение — переменные `LLM_PROVIDER`, `LLM_BASE_URL`, `LLM_MODEL`.

Модели по умолчанию:
* Ollama — `qwen3.5:4b` (3,4 ГБ, Apache 2.0, русский язык, JSON по схеме, режим размышлений выключаем `think=false`) — расшифровка и категоризация кластеров, вся разработка и отладка промптов.
* OpenRouter — `qwen/qwen3.8-flash` ($0,15 / $0,47 за миллион токенов на вход / выход, то есть ≈ 13 ₽ / 41 ₽ по курсу ЦБ 86,89 ₽ за доллар на 04.09.2026) — письма на отписку и LLM-судья, где нужна модель сильнее локальной. Если модель не поддерживает `response_format`, адаптер сам переходит на JSON в промпте с валидацией.

**Почему.** Ollama даёт бесплатную и офлайновую разработку на 10 параллельных запросов; OpenRouter закрывает качество текстов без второго SDK и второго счёта. Один интерфейс — значит, промпты AI-2 не зависят от того, где крутится модель, а кэш общий.

**Лимит расходов.** Ключ OpenRouter создаётся с жёстким лимитом **$10 (≈ 870 ₽)** на весь хакатон. Оценка: полный прогон обогащения по 10 профилям ≈ 150 запросов ≈ $0,03; письма для 25 подписок ≈ $0,02; сто прогонов за четыре дня не превысят $5. Ключ хранит тимлид, в репозиторий — только `.env.example`. Проверка баланса — на вечернем демо.

**Следствие.** Все ответы моделей кэшируются в `cache/llm_cache.json` по хэшу входа; перед защитой кэш прогревается на демо-профилях, а на самой защите ставится `LLM_OFFLINE=1` — сеть не нужна.

## D3 · 04.09 · Контракт данных v0.1 и идентификаторы

**Решение.** Контракт — `docs/contract.md` и `backend/app/models.py`, версия `0.1`. Идентификатор транзакции `t_NNNNNN` — порядковый номер строки в исходном файле. Опорная дата всех расчётов — последняя дата выписки, а не «сегодня».

**Почему.** Номер строки позволяет стенду AI-1 сопоставлять ответ с `labels.json` без отдельного поля; опорная дата в выписке делает результат на демо-файлах воспроизводимым в любой день.

**Следствие.** AI-1: индексы в `labels.json` — внутри файла профиля (0-based), не сквозные по всем профилям (сейчас они сквозные — переделать в v2 генератора).

## D4 · 04.09 · Формат входного CSV

**Решение.** Эталон — `Дата операции;Категория;Описание операции;Сумма;Валюта` (csv-ru). Формат `operationDate, merchant, amount, type, status, category, mcc` из `ai research/main.py` тоже принимается (csv-en). Колонки распознаются по синонимам, новые названия банков добавляются в `COLUMN_SYNONYMS`.

**Почему.** Реальных выписок нет; два формата покрывают и наш генератор, и данные, на которых уже тестировался код AI.

## D5 · 04.09 · Один бэкенд

**Решение.** Логика из `ai research/main.py` (словарь сервисов, алиасы, исключения, MCC) переносится в `backend/app/config.py` и `services/detector.py`; папка `ai research/` после переноса удаляется из `main`. Дальнейшая разработка обнаружения — только в `backend/`.

**Почему.** Два сервиса с разными контрактами — гарантированный конфликт в воскресенье.

**Следствие.** Из кода AI в v1 уже взяты: список известных сервисов, часть алиасов, идея исключения покупочных категорий. Не взяты: балльный скоринг (заменён формулой уверенности) и `biweekly` (нет в контракте, добавим, если стенд покажет потребность).

## D6 · 04.09 · Правила работы с репозиторием

**Решение.** `main` защищён; работа в ветках `feature/<роль>-<что>`; PR ≤ 300 строк; ревью тимлида в течение 2 часов, второй ревьюер — AI-1. Прямые пуши в `main` запрещены.

**Почему.** Уже дважды разруливали конфликты при пушах в `master` всемером.

## D7 · 04.09 · Спорные случаи для `definitions.md` (PM, до субботы)

Требуют решения PM с тимлидом, пока стенд не начал считать метрики:

1. **Образовательные рассрочки** (Skillbox 5 000 ₽/мес). В разметке AI-1 — подписка; в коде AI — «не подписка» (рассрочка). Предложение: не подписка — это кредитный продукт, отменить его «в один тап» нельзя; в разметку добавить как отрицательный пример.
2. **Две транзакции** («Литрес» у студента). По правилу «минимум три» не находится. Предложение: оставить правило, в разметке пометить `expected_detectable: false`.
3. **Связь** (пополнение МТС 650 ₽). Считаем подпиской категории `telecom`, если сумма стабильна; пополнения на разные суммы — нет.
4. **Ежемесячные покупки в одном магазине** (например, 3 похожих чека на АЗС). Не кандидаты, если банк дал покупочную категорию; без категории — находятся с жёлтой уверенностью, пользователь отклоняет кнопкой «Это не подписка».
